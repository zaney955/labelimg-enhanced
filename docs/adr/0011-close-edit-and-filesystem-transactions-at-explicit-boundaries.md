# Close edit and filesystem transactions at explicit boundaries

Image navigation must cancel and restore any pending drawing or annotation gesture before the controller selects another image. Ordinary manual Save and Save As and storage-format changes are rejected, and autosave is not scheduled while an edit or history-step token is open. An accepted batch review, explicit annotation-document loading, workspace switching, and close cancel the token back to its source snapshot before reading dirty state or writing another resource; declining batch confirmation preserves it. A token therefore belongs to exactly one current image and can never be silently abandoned by navigation or consumed by a timer-fired Canvas capture.

Delete and clear operations treat one image plus all of its matching annotation resources as one logical target. If any recycle move for that target fails, every resource already moved for that target is restored before processing continues. A partial rollback carries forward only identities still available in trash; repeated shared-CreateML rewrites coalesce the first original identity with the final operation fingerprint. Review recovery revalidates fields and captures rollback bytes only while holding all affected storage-resource leases. A missing empty Pascal target is validated as the empty-unreviewed state. Every attempted resource is rollback-eligible before its writer is invoked, covering a successful commit followed by fingerprint or derived-index failure, and dirty candidate overrides are rebuilt after success or rollback. Cleanup of obsolete backups after a committed recovery is non-fatal.

Silently clearing an open edit token, writing a mutable Canvas mid-gesture, and reporting a partially removed image target as successful are rejected because they make history, saved baselines, and recovery evidence disagree.
