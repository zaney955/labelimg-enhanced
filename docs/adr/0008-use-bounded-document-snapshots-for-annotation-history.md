# Use bounded document snapshots for annotation history

Annotation Undo and Redo will be owned by a deep `AnnotationHistory` module whose small interface records atomic edits, moves per-image history positions, tracks saved baselines, rebases externally replaced documents, and enforces retention limits. The module will retain immutable annotation-document snapshots plus transition descriptions and affected-object metadata instead of exposing a separate reversible command type for every editing operation, because uniform complete states make bulk edits, atomic failure recovery, redo branching, and dirty-state calculation easier to verify. Snapshots contain annotation state and session identities but never copy image pixel buffers; they share only read-only image identity and dimensions. Per-image limits of 100 edits and a soft workspace target of approximately 256 MiB bound the additional memory cost, while one complete newest atomic entry may temporarily exceed that target after other history is evicted.

The rejected alternative is a reversible command class for each Canvas and MainWindow mutation. That design would spread inverse logic across creation, deletion, geometry, review, paste, format adapters, and future operations, making partial batch failure and exact annotation-order restoration difficult to prove. Recording arbitrary `set_dirty()` calls is also rejected because the current signals fire during mouse movement and mix annotation content with view and preference changes. All history-producing paths must instead pass through one annotation edit transaction and one guarded snapshot projection.
