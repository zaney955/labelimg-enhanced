# Coordinate annotation saves by physical resource

Annotation saves will be coordinated by the complete set of physical resources they touch rather than only by image path. Independent Pascal VOC files can be written independently, while YOLO writes that share a class vocabulary and CreateML records that share one JSON collection must serialize through the same resource coordinator. Requests waiting on one resource retain only each image's latest requested immutable revision; shared CreateML revisions may be coalesced into one collection transaction. Baselines advance only for the exact revisions included in a fully successful write.

Every write first verifies the retained resource fingerprint. Single-file and shared-collection updates use a peer temporary file and atomic replacement; multi-file YOLO updates stage every output and use rollback-capable replacement before confirming success. A conflict belongs to the physical resource, so an externally changed CreateML collection pauses every dependent image and can only be reloaded or overwritten as a complete collection. Per-image-only queues and per-record CreateML conflict resolution are rejected because they permit lost read-modify-write updates.
