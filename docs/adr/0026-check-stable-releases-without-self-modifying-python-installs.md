# Check stable releases without self-modifying Python installs

LabelImg Enhanced will issue one ordinary GET to GitHub's public `/releases/latest` web redirect asynchronously at application launch no more than once every 24 hours, and on demand from Help. The update check does not call the rate-limited REST API and does not use HEAD because some network proxies close that method. GitHub selects the published non-prerelease release; the application then accepts only a strict stable tag and canonical project URL, compares semantic versions, caches successful release metadata, and presents newer versions in a non-modal notice. Python installations may copy an explicit `python -m pip install --upgrade <wheel-url>` command, but the running application will never execute package-manager commands or modify itself. Users may defer a notice for 24 hours or ignore exactly one version, while automatic failures remain silent and manual failures remain visible.

Tagged releases will be built by CI only from annotated `vMAJOR.MINOR.PATCH` tags that exactly match the package version. The workflow runs the complete test suite, validates the universal wheel identity, publishes hashes and build provenance, and creates a draft GitHub Release for manual publication. ADR 0027 adds an explicitly unsigned managed Windows installer without changing the rule that Python installations never modify themselves.
