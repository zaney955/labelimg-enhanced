# UI 设计规范

本规范适用于新增和修改的窗口、面板、菜单、控件、主题、图标、文案及自绘界面。实现前先按本规范确定信息结构与交互，再选择共享组件；完成时按末尾的流程验收。目标是让新增功能自然融入现有桌面工作台，而不是靠更换颜色掩盖临时拼装的布局。

本文件维护通用设计规则；[全局界面外观](ui-presentation.md)维护现有组件与呈现细节，[文档导航](../README.md)链接功能专题。通用规则在这里修改一次，专题只补充自身的行为和约束。功能的数据范围、菜单归属、快捷键和事务语义沿用对应专题，外观重构不改变这些行为。

## 设计取向

- **画布优先**：单图标注是主任务。持续使用的辅助信息放入停靠面板；左侧工具栏只承载 Canvas 工具；批量文件管理保持次要层级。
- **结构先于装饰**：先明确用户任务、操作对象、输入、结果和主操作。用对齐、留白、表面层级与少量分隔表达分块，标题字号只辅助层级。
- **同类问题使用同一范式**：共享标题栏、查询入口、选择反馈和底部操作区。布局按任务变化，组件规则保持一致。
- **稳定入口**：常用命令位置稳定，同一命令的菜单、按钮、快捷键和上下文入口复用动作与用例。菜单职责见[菜单信息架构](menu-information-architecture.md)，可见工作台入口见[Canvas 命令布局](canvas-tool-rail.md)。
- **信息就近**：输入和影响它的设置放在一起；结果、进度和失败原因靠近对应操作；底部只放当前任务的提交或选择操作。
- **克制表达**：正文只解释做决定所需的信息。避免重复标题、装饰性图标卡、无任务含义的卡片、每行一个边框和过多嵌套分区。

## 选择界面范式

| 任务 | 使用的结构 | 设计要求 |
| --- | --- | --- |
| 持续辅助标注、浏览文件、查看检查结果 | 可停靠面板 | 标题栏 → 上下文区 → 可伸缩列表 → 按需显示的底部操作区 |
| 简单参数或设置 | 任务对话框 | 清楚的标题、按含义分组的字段、固定底部操作；无需展示与选择无关的预览 |
| 搜索和筛选 | 查询行与锚定筛选浮层 | 常用查询可直接输入；高级条件按类别/状态分块；显示生效条件并能单独清除或全部清除 |
| 批量替换、重命名等规则处理 | 规则与结果分栏 | 输入规则与结果预览分开；作用范围、影响数量和提交状态明确 |
| 图像处理 | 大图预览与参数侧栏，或已有的画布内交互 | 参数改变应能评估图像结果；确认、取消及必要的撤销/重做始终可达 |
| 统计与明细 | 关键数量、图表和结果表格 | 数字具有清楚含义；筛选条件靠近结果；保留扫描中、空结果和刷新状态 |
| 关于、更新等信息任务 | 身份/任务状态、必要元数据、对应操作 | 不堆叠重复标题与说明；每个阶段只有一个视觉主操作，次要操作弱化 |

先复用已有范式。确有不同任务结构时，把可复用部分补入共享呈现层并同步本规范，避免为一个功能建立第二套控件风格。外观设置沿用模式分段与具名色板，不增加预览区；具体行为见[主题接口](themes.md)。

## 面板与工作区

面板边界由工作区间隔、外边框和标题栏表面共同表达，不能让画布、边栏与多个面板成为一块无法辨识的同色区域。

| 区域 | 放置内容 | 约束 |
| --- | --- | --- |
| 标题栏 | 功能图标、短标题、紧凑计数、全局面板操作 | 使用 `PanelHeader`；高频操作直接可见，低频操作进入更多菜单 |
| 上下文区 | 当前作用范围、必要路径、默认行为、搜索与筛选 | 共用内边距；查询在所控制的列表上方；完整长路径放入提示 |
| 列表/结果区 | 实际条目、实例、表格或对应空态 | 占用剩余空间，内容可滚动；避免给每条记录再套独立卡片 |
| 底部操作区 | 已选数量与针对所选对象的操作 | 无选择时按功能隐藏；不随结果列表滚走；出现时不挤出屏幕 |

使用 `panel_body`、`panel_context`、`panel_list` 与 `present_panel` 组合，标题和内容分别接入主题。保留原生调整尺寸、拖动、浮动/停靠、页签组合和布局恢复；位置菜单提供不依赖拖动的操作方式。自定义标题栏完整提供 `sizeHint()` / `minimumSizeHint()`，验证标题动作不被内容遮挡。

面板尺寸允许随内容和屏幕收缩；多个面板及选择操作同时出现时，窗口仍须适合可用桌面。可见功能入口不能因为布局重构消失。

## 布局、排版与控件密度

以逻辑像素设计，由 Qt 处理 DPR。优先调用共享组件取得尺寸，不为每个功能复制一组独立常量。现有基线见[组件呈现](ui-presentation.md)：

| 项目 | 基线与使用方式 |
| --- | --- |
| 间距 | 紧凑控件内部使用 4/6，相关内容使用 8/12，大分区使用 16/18；同一行、同一区域取一致值 |
| 面板 | 标题栏 38，标题图标 16，标题动作 26；上下文和列表边距由面板辅助函数维护 |
| 紧凑列表 | 标注行 32；文件行至少 32，并随字体增加；搜索输入沿用现有 28 的紧凑样式 |
| 对话框 | 外边距、分区、主次按钮及底部间隔由 `present_dialog` / `section` 维护 |
| 字体层级 | 使用 `heading`、`sectionTitle`、`supporting` 等角色；字体令牌集中在 `ui/typography.py`，正文 13、辅助信息 12 个逻辑像素，不在局部重新声明字号 |
| 边框与圆角 | 使用共享样式的细边框和小圆角；同一种组件使用同一几何，不叠加额外阴影与装饰框 |

控件标签、输入起点和结果列保持对齐，相关内容之间的距离小于不同分区之间的距离。数量和单位靠近对应对象；长文件名和路径按已有规则省略并保留完整提示。正文用普通字重，强调只用于标题、关键数值和选中状态。

窗口使用布局、伸缩与滚动，不用绝对坐标拼页面。长说明可换行；复杂内容在有限空间内滚动，确认/取消等底部操作留在滚动区域外。固定高度只用于已定义的紧凑组件，不固定会随语言和字体增长的整段内容。

## 颜色、主题与图标

所有应用界面颜色从 `labelimg.ui.theme` 取得；功能组件不得写死浅色/深色 RGB，也不单独建立调色板。颜色模式与强调色独立，新增界面必须同时支持浅色、深色、系统跟随和所有已注册强调色。

| 表达目的 | 语义角色 |
| --- | --- |
| 窗口和内容层级 | `background`、`surface` |
| 工作区与面板边界 | `workspace_gutter`、`panel_header`、`panel_border`、`divider` |
| 正文与辅助文字 | `text`、`muted` |
| 主操作与焦点 | `accent`、`accent_hover`、`on_accent`、`accent_border` |
| 控件选项的浅色强调 | `selected` |
| 列表整行选择 | `selection_background`、`selection_border`、`selection_foreground` |
| 禁用、警告、破坏性操作 | 对应的 `disabled_*`、`warning`、`danger` 等既有角色 |

QSS 通过 `theme_style()` 和 `apply_theme_style()` 绑定；自绘控件在绘制时读取 `COLORS`，主题变化后刷新，不能缓存旧主题的颜色。新增颜色需求先检查现有语义角色；确需新角色时，同时补齐各模式生成、接口校验与对比度测试。完整扩展流程见[主题接口](themes.md)。

正文、辅助文字及文字/按钮/选择底色的关键组合至少达到 4.5:1；功能性图标和焦点标识至少达到 3:1。低对比装饰分隔线不能承担唯一的状态或交互提示。状态还须通过文字、形状或描边表达，不能只靠红绿或强调色辨别。

图像像素、类别颜色、实例色块和统计图数据保留数据语义，不能被界面强调色覆盖。操作图标复用[SVG 图标系统](../icon-design-system.md)和 `labelimg.ui.icons`，维持相同的轮廓、线宽与尺寸语法；不用 emoji 或文本字符冒充操作图标。Qt 默认控件也要接入统一呈现，覆盖勾选、下拉、滚动条、进度、禁用和弹出菜单。原生文件选择器与操作系统窗口边框保留平台外观。

## 选择与交互状态

每个交互组件都应区分正常、悬停、键盘焦点、按下/选中、禁用和忙碌状态；按功能补齐空结果、错误和完成状态。悬停与焦点只表示当前操作位置，不改变实际选择，也不掩盖已选对象。

| 列表状态 | 统一呈现 |
| --- | --- |
| 文件多选 | 所有已选行使用相同的不透明主题底色、细圆角边框和可读文字；焦点移到菜单或批量操作后保持 |
| 标签类别全部选中 | 整行主题底色、实线边框、加粗类别名；计数保留该类总数 |
| 标签类别部分选中 | 同一整行主题底色、虚线边框、普通字重，显示已选数/总数，例如 `1/3` |
| 当前项与活动实例 | 使用各自既有语义，不能让其余已选行看起来未被选择 |
| 隐藏/被筛选的已选对象 | 保留选择与数量提示；显示变化不静默清空选择 |

标签选择不使用左侧细条或圆点表达全选/部分选中；类别色标继续表达类别颜色。实例编号、类别描边和选中填充保留自身语义。计数列预留空间，选中状态变化不移动实例按钮或状态列；极窄视图省略长计数并提供完整提示。

Ctrl/Shift、键盘导航、右键目标、双击编辑和快捷键遵循原有选择契约。呈现层投影功能状态、发出操作意图，不建立第二份选择、复核或保存状态。状态变化由所属功能统一执行；界面失败时应恢复真实状态，不能留下错误的勾选反馈。

空态说明当前没有什么，并按需要提供一个有效入口，例如打开目录或清除筛选；不重复页面标题或放置大段教学文字。异步任务保留必要的取消、进度和失败信息，避免阻塞 GUI 线程。

## 文案与可访问性

- 应用文案只提供简体中文和英文，加入统一消息目录；常驻窗口支持即时切换。路径、用户类别、文件名、格式名和原始系统诊断保持原文，细则见[双语界面](bilingual-interface.md)。
- 命令标题使用短动宾词，例如“向右旋转”，不把实现原理或整段操作说明塞进按钮。补充说明放到状态提示；工具提示包含现有快捷键。通过 `set_action_copy()` / `format_action_tooltip()` 与共享动作同步。
- 标签说明字段含义，placeholder 只给输入提示；需要持续辨识的字段不能仅靠 placeholder 命名。
- 图标按钮提供本地化提示与可访问名称；输入关联标签，保留合理 Tab 顺序和键盘焦点。动作所在上下文、禁用原因和操作结果可辨识。
- 中英文保持同一信息结构。为英文长度和字体回退留空间，不能用裁切、压缩字号或隐藏命令解决布局不足。
- 破坏性操作及写入行为沿用已有事务约束；作用范围、未保存内容与不可逆后果等影响决策的信息在操作前可见。诊断详细内容可以折叠，关键失败原因不能只留在日志。

先查看同类组件的现有使用方式，再组合新界面。共享呈现层负责风格和通用布局，功能 UI 负责数据投影与用例调用；业务规则仍留在所属功能，参见[模块化架构](modular-architecture-refactor.md)。

## 新增功能流程与验收

1. **确定任务与入口**：明确操作对象、作用范围、输入、结果、主操作及菜单归属；能指向对应功能设计和复用的界面范式。
2. **组织布局与状态**：确定面板/对话框结构、主次操作、空态、忙碌、错误、全选/部分选择、取消或失败后的状态；检查窄窗口和长路径的安排。
3. **接入共享组件**：使用上表中的呈现、主题、图标、动作和语言接口。修改共享规则时同步规范；发现同一规则的局部副本时收敛到共享实现，不把旧界面的例外复制到新功能。
4. **验证实际行为与渲染**：下面适用项全部有证据后再认定完成。
5. **同步交付信息**：更新所属功能设计；报告行为变化、实际测试结果、渲染覆盖与限制。运行环境安装按当次任务范围处理，构建或解包测试不等于已更新用户环境。

界面实现的验收要求：

- 操作保留原有数据语义、菜单职责、快捷键、取消/回滚与历史记录；测试覆盖真实手势和可观察状态，不能只检查样式字符串。
- 受影响界面检查简体中文/英文、浅色/深色和 100%/125%/150% 缩放，覆盖窄窗口、长文本与长路径。布局变化检查标题、列表、底部操作和弹出菜单不重叠、不被裁切，实际按钮仍可点击。
- 新增主题角色、自绘或选择样式时，对全部已注册强调色与两种模式检查对比度及相关渲染；系统跟随另验证模式变化与手动模式隔离，不能只看一张静态截图。
- 停靠布局变化覆盖移动、浮动/停靠、调整尺寸、页签组合、保存恢复，以及多个面板与底部选择操作同时显示。控件生命周期变化检查语言/主题切换与应用退出。
- 从受影响功能回归开始，跨功能行为或共享组件变化运行源码全量；资源/打包变化另校验构建包。测试使用隔离设置与临时数据，不能为渲染修改用户图片或标注。失败、跳过、重试及未覆盖范围分别报告。
- 使用真实 Qt 控件生成 PNG 与状态清单并检查画面。Qt offscreen 不能确认的原生窗口弹出行为、系统边框及平台对话框单独说明；不能把样式校验或隐藏控件渲染当作真实桌面验收。

测试入口见根目录 [开发与验证](../../README.md#开发与验证)。[通用渲染工具](../../tools/render_ui_gallery.py)支持模式、强调色、语言和缩放；面板可用 `--panels-only`，标签选择使用[标签渲染工具](../../tools/render_label_selection.py)。覆盖清单随功能维护，不把一次运行的截图数量写成永久验收标准。纯文档改动检查规范一致性、链接和命令/API 的有效性，无需重跑无关界面测试或安装程序。
